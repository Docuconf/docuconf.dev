# Get involved

docuconf is at the stage where a single good comment can change the design. The most useful things you can do right now:

- **Review the specification.** Read [SPEC.md](https://github.com/Docuconf/docuconf-go/blob/main/spec/SPEC.md) and open an issue on anything unclear, wrong or missing. Its open questions section lists what is still undecided.
- **Bring your edge cases.** If your platform has bitten you with environment config in a way not yet in [EDGE_CASES.md](https://github.com/Docuconf/docuconf-go/blob/main/docs/EDGE_CASES.md), tell us.
- **Try an SDK in a real app.** Each of the <SdkCount /> SDKs is a v0.1 alpha. Start from [Get started](/languages/) and open an issue on that SDK's repository wherever it does not fit how your ecosystem works.
- **Help an SDK.** Each SDK should be shaped by people who live in its ecosystem. If you know its host library well, review its README and example, and tell us where it fights the library instead of extending it.
- **Bring a new language.** The [SDK requirements](/spec/sdk-requirements/) say what an SDK must do, and the shared conformance suite checks it.
- **Try the schema.** `spec/cue/test.sh` runs the CUE meta-schema against valid and invalid examples. Add a case that should fail and does not.

## Where things live

Everything is under the [docuconf GitHub organization](https://github.com/Docuconf). This website has its own repository, `docuconf.dev`. Each SDK has its own repository:
